# 角色文档：后端工程师

## 目标
- 把“偶发可用”提升到“稳定可用”。

## 服务拆分建议
- `OCR Service`：只负责图文识别。
- `Analysis Service`：只负责报告生成。
- `Gateway`：参数校验、鉴权、限流、错误码标准化。

## 关键任务
1. `P0` 增加限流（按 IP + UA）。
2. `P0` 统一错误码和用户友好文案映射。
3. `P0` 增加请求追踪 id（写入响应头与日志）。
4. `P1` 增加异步任务队列（超时任务可恢复）。
5. `P1` 增加模型路由策略（按可用性自动降级）。
6. `P2` 增加报告缓存（同输入短期重复命中）。

## SLO
- API 可用性 >= 99.5%。
- 5xx 比例 < 1%。
- 模型超时率 < 8%。

## 验收标准
- 同一份截图在 3 次重试内，成功率 >= 90%。
- OCR 和分析报错均可定位到具体 provider/model。
